# 私密云备份与恢复

同步不是备份。当前保留 JSON v3、五份本机恢复点和独立于 Supabase 的私密快照。Git 只保存本说明、SQL 和验收代码；不保存快照、真实学习历史、邮箱、Auth UUID、token 或密码。

`scripts/cloud-backup.sql` 是单条只读 MVCC 快照：学习事实、当前 checkpoint、设置、已提交水位及待处理云 fork。未来接手先核对实际 schema 与字段，不能机械执行过期 SQL。保存为时间戳 JSON，上传本人私密文件夹，读回并核对关键字段。保留旧备份；保存失败不能把当天标为成功。

目前已保存一份冷启动账户的私密快照，读回成功；恢复到干净本机数据库的原子导入通过。每日私密备份任务已建立，依赖现有 GitHub / Supabase / Library 连接持续有效；首个定时执行尚未发生。任务失败时提示本人，不把配置成功说成无人维护保证。

## 恢复到新的电脑

1. 下载本人私密 JSON，使用 `node scripts/verify-cloud-backup.mjs /绝对路径/backup.json` 验证；该命令只打印计数，不上传数据。
2. 在干净浏览器的文研设置中导入 JSON。核对词数、学习设置和续学组；离线可继续学习。
3. 登录同一 owner 后正常同步。导入事实保留原 ID；导入旧备份不会回滚已经存在的 checkpoint 或替换原作答历史。

## 云数据库损失后的恢复

保留原 Auth 身份时，先应用 migration、检查唯一 owner 和注册关闭状态。用干净本机导入快照并上传，然后核对云事实计数/水位和另一环境恢复。已经与旧数据库绑定游标的设备要先导出本机记录，使用干净恢复环境，不能直接清空未同步数据。Auth 身份也损失时先恢复本人身份与单 owner 绑定，不能把别人账户绑定为本人。

`cloudForks` 保留待处理进度证据，当前导入器不会自动把它们伪装成新作答。需要人工选择其 checkpoint 后再恢复；始终保留原私密 JSON。收据与已失效 session/token 不属于可移植学习备份，不恢复秘密。

云快照不知道未联网设备的 outbox；离线新增记录仍须由该设备导出。只有已提交云事实能进入异地快照。当前仅演练冷启动快照的本机恢复，尚未演练托管数据库灾难恢复，不能宣称该项已完成。
