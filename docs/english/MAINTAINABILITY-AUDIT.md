# Wenyan 英语可维护性审计

更新：2026-10-07。

本文的旧结构观察对应main v1；#12已收敛渲染接口但尚未合入。下一阶段把session checkpoint与事实分离、加入可重建投影是已选定设计，尚未实现；不再把localStorage/schema 2当永久约束。当前状态见开发进度，职责见ARCHITECTURE。

本文件记录英语代码审计。目标不是追求“零常量”，而是把会影响长期维护、部署和数据正确性的隐式硬编码收敛到稳定边界。

## 本轮已处理

1. **配置散落**：新词额度、组上限、错词窗口、列表上限、TTS、词库层级、英语 storage key 等集中到 `src/english/config.js`。
2. **事件 key 规则散落**：`word:<id>` 统一通过 `src/english/keys.js` 生成和解析。
3. **错词判断重复**：队列与详情状态共用 `src/english/events.js` 的错误语义。
4. **测试隔离缺口**：词库层级改走 `storage.js` scoped local wrapper，`?test=...` 不再碰真实偏好。
5. **部署路径硬编码**：英语数据通过 Vite `BASE_URL` 解析，并将构建 `base` 设为相对路径，支持根路径或项目子路径静态部署。
6. **缺失排名哨兵值**：去掉 `99999 / 90000`，缺失 rank 明确使用 `null`。
7. **旧数据统计偏高**：没有 `firstCorrect` 的旧 review 仍计入复习量，但不进入首次正确率分母。
8. **重复词规范化丢信息**：`may/May`、`march/March` 保持一个稳定学习 ID，但合并释义、词频、排名与分类信息，不再静默丢第二行。
9. **英语兼容数据混在文学内容里**：旧 24 词已移动到 `src/english/fallback.js`，只负责兼容和故障降级。
10. **运行时注入样式**：空 IPA 的展示规则回到英语 CSS，不再由数据加载模块注入 `<style>`。

## 已确认但刻意后置

这些不是“没看到”，而是不应在桌面真实验收前和本轮重构混在一起：

1. **英语页二次装饰耦合**：`app.js` 先渲染，`english-vocab.js` 再通过 `MutationObserver` 补 badge、来源说明和词库层级。真实桌面使用证明有维护成本后，再独立收敛成明确的英语渲染边界。
2. **未完成 session 的全局只读 hook**：词库层目前通过 `globalThis.__wenyanActiveEnglishSessionIds` 获取需要保留的词。行为清楚但接口不够正式，后续可与英语渲染 / 状态边界一起整理。
3. **到期词排序不是真正按逾期程度**：当前“到期优先”成立，但多个到期词内部仍主要跟随词库顺序。真实使用后再评估是否按 due 时间 / 逾期程度排序。
4. **session 事件日志会膨胀**：每次 session 更新都会追加包含完整 queue/results 的事件。长期使用和备份体积真实增长后，再设计安全压缩，只保留需要的最新 session 状态而不伤害学习历史。
5. **复习排程计算可能随历史增长变慢**：`wordCounts()` 对已学习词重复调用 `reviewCard()`，而 `reviewCard()` 会重放历史 review。应使用真实长期数据 profiling 后决定是否做派生 card cache / 索引，避免现在提前造缓存系统。
6. **核心 1200 的产品质量**：纯词频层会含大量用户早已掌握的基础功能词。优先考虑“快速标已掌握 / 快速筛词 / 基于真实学习记录调整新词池”，不要再硬编码一份主观黑名单。

## 维护原则

- 业务常量可以存在，但必须集中、命名、可测试；“零常量”不是目标。
- 内容数据与逻辑配置分开。
- 当前运行版不静默破坏记录；云基础允许按明确升级方案替换v2存储协议，稳定word ID/首次答题语义/FSRS与JSON保留。实施前重新核实是否新增真实数据。
- 不引入框架、依赖注入、通用配置中心等与单人工具不匹配的工程复杂度。
- 所有行为变化必须有测试和构建验证。
- 桌面真实验收前优先保证稳定与可恢复，不为了代码洁癖大拆已工作的训练流程。
