# Wenyan 英语桌面真实使用验收

目的：在把当前整合基线合入 `main` 前，确认英语核心闭环在**真实桌面浏览器运行时**中可以稳定连续使用。

这里严格区分三层证据：
1. Node 自动测试 / 构建。
2. Chromium 对真实 `dist` 静态产物的浏览器闭环验收。
3. 本人长期日常使用后的体验结论。

前两层可以作为合入 `main` 的工程门槛；第三层属于合并后的真实使用阶段，不把“还没连续用了几天”当成无限阻塞基线的理由。

## 0. 验收对象

当前验收对象：

`integration/desktop-english-baseline-v1`

对应 Draft PR #11，整合了此前 PR #2—#10 的最新有效英语成果。

当前不做 Android / iOS 验收。

## 1. 自动门槛

标准 CI：

```bash
npm ci
npm test
npm run build
```

浏览器 smoke 使用 Chromium 直接运行 `npm run build` 生成的 `dist`，不是 mock 页面，也不是把 Vite dev server 冒充生产构建。

隔离测试继续使用 `?test=<scope>`，不会写入真实个人学习记录。

## 2. 桌面环境

当前自动浏览器证据：
- Ubuntu 24.04 GitHub runner。
- Node 24。
- Playwright 1.63.0，仅 CI 临时安装，不进入正式运行依赖。
- Chrome for Testing / Chromium 153。
- 1440 × 900 桌面视口。

真实日常使用阶段仍应继续观察本人常用 Windows 浏览器中的键盘节奏、字体和长时间使用感受；这些属于产品体验反馈，不是当前已发现的数据安全阻塞。

## 3. 固定词库与层级

验收要求：
- 默认主词库不是 24 个兼容词。
- 核心层正式规模 1200。
- 高频层正式规模 2444。
- 完整层正式规模 5528。
- 兼容旧记录而额外保留的种子词，不得被混进“正式层级规模”。
- 未完成 session 临时保留的低频词，要单独标记为续学保留。
- 完整层搜索可以找到未出现在默认可见列表中的低频词。
- 切换层级不破坏当前未完成 session。

本轮 Chromium smoke 第一次运行时真实发现：**高频层被显示成 2448**。原因不是词库多了 4 个正式高频词，而是 4 个旧 v0.1 兼容词被混进 `active` 层级计数。

已经修复为三个独立概念：
- `active`：正式层级规模（1200 / 2444 / 5528）。
- `compatibility`：为旧学习记录保留、但不属于当前正式层级的兼容词。
- `carryover`：只为未完成 session 临时保留的续学词。

修复后根路径和子路径 smoke 均验证：
- 核心 1200。
- 高频 2444。
- 完整 5528。
- 完整层可以搜索到最低频测试词 `zoom`。

## 4. 三种训练模式

### 跟打
已自动验证：
- 跟打能连续推进。
- 只产生 `typing`，不会产生主动 `review`，因此不冒充 FSRS 记忆成功。
- 自动连续完成 24 词后，再创建 6 词组继续完成，总计连续 30 词，正常进入结果页。

仍属于日常使用观察项：长时间人工输入时的主观节奏和焦点舒适度。

### 默写
已自动验证：
- 可以只根据释义输入英文。
- 故意首次答错后进入完整订正。
- 输入正确词后才能继续。
- 完成订正后进行 FSRS 评价。
- 训练推进后刷新，能够回到正确 session index。
- 点击提示后 `hinted:true` 立即持久化；刷新后仍保留。

### 听写
已自动验证状态语义：
- 可以进入听写模式。
- 使用提示后答题 / 评价能够正常推进。
- 产生的 review 保留 `hinted:true`。
- 即使浏览器音频环境不可用，训练状态不因此损坏。

**未宣称自动验证“声音真的从扬声器听得到”。** Headless CI 不能替代本人电脑实际听音；TTS 可听性放到固定桌面入口后的真实使用观察。

## 5. 智能队列与错词

已有 Node 自动测试保护：

```text
到期 → 近期错词 → 新词
```

并覆盖：
- 近期错词派生。
- 后续正确清除旧错词派生状态。
- undo 对错词状态的影响。
- 队列去重和上限。

浏览器 smoke 同时验证真实训练会产生 review / typing 事件并正确续学。

完整“制造多种真实长期到期卡后观察优先级”继续属于实际使用后的调度优化阶段，不阻塞当前基线。

## 6. Session 完整性

浏览器层已经验证：
1. 开始训练后完成首词并推进 index。
2. 刷新后继续同一未完成词组。
3. 点击提示但未提交时刷新，`hinted` 不丢失。
4. 有未完成组时英语页只提供“继续上次”，不会再出现会覆盖它的新智能开始入口。
5. 点击继续后仍保持原 index。
6. 在核心层恢复一个完整层最低频词组成的未完成 session，正式词库加载后该词会作为 `carryover` 保留并可继续训练。

旧 v0.1 种子词兼容另有 catalog / session 自动测试保护。

## 7. 单词详情

当前代码和 Node 测试已覆盖：
- 音标。
- 中文义。
- 考研排名 / 词频。
- 分类 / 子分类。
- 变体。
- 词形变化。
- 学习状态。
- 近期错词 / 收藏。

- `may / May`、`march / March` 规范化重复项合并义项，不静默丢数据。

固定 ECDICT 当前没有可靠 `pos` 覆盖，因此继续不展示假词性。

随机多词人工视觉抽查属于合并后真实使用反馈，不再作为数据正确性的阻塞项。

## 8. 今日轻量反馈

Node 自动测试已保护：
- 今日新学只看第一次主动回忆；跟打不冒充新学。
- 主动复习只统计 review。
- 首次正确率排除提示、首次拼错等情况。
- 拼写错误语义统一。
- 旧 review 缺少 `firstCorrect` 时不污染正确率。
- undo 走同一活跃事件语义。

## 9. 键盘与连续训练

Chromium 自动连续完成 30 个跟打词：
- session 连续推进。
- 第二组能正常创建。
- 最终进入结果页。
- 未出现未捕获页面异常。
- 1440px 视口无横向溢出。

这已经覆盖“连续操作是否会把状态机跑坏”的工程风险。

真实 Windows 键盘手感、Enter / Esc 是否符合个人习惯，继续在每日使用中调整，不在合并前凭空继续加快捷键。

## 10. 长列表与搜索

已经自动验证：
- 完整层总数 5528。
- 页面不会把全部词无上限铺成列表（代码仍有限制）。
- 完整层能搜索到最低频测试词 `zoom`。
- 根路径 / 子路径都能正确加载固定 NETEM 和 ECDICT 静态数据。

长期学习事件达到数千 / 数万后的 review 计算性能仍需真实数据 profiling；当前不提前造缓存系统。

## 11. JSON 备份恢复

本轮不是只验证“能导出 JSON”。Chromium smoke 已实际完成：
1. 产生真实英语学习事件和未完成 session。
2. 导出完整 JSON 文本。
3. 新建干净 browser context。
4. 将导出的 JSON 通过应用自己的“粘贴备份”入口重新导入。
5. 验证导入事件数量不少于原备份。
6. 验证未完成 session 的 index 被恢复。
7. 点击“继续上次”后真实进入训练页，并确认仍处于相同 index。

因此当前备份闭环已经具备浏览器级回归保护。

## 12. 静态部署路径

Vite 使用相对 base。

浏览器 smoke 每次构建后会把**真正的 `dist` 静态产物**同时部署到两种测试路径：
- `http://127.0.0.1:4173/`
- `http://127.0.0.1:4174/desktop/`

同一套完整 smoke 在两种路径各跑一次，均需通过。这直接保护后续 GitHub Pages / 其他项目子路径部署场景。
