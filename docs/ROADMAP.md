# Wenyan 路线图

路线图只解决一件事：**下一步应该做什么，以及什么暂时不要做。**

Wenyan 是单人考研工具，不按商业产品路线扩张。当前阶段采用 **English-first**：先把英语词汇训练做成可以每天长期使用的完整模块；文学内容、真题关联和文学“今日任务”暂缓，等英语稳定后再恢复。

优先级始终是：真实备考价值 > 数据安全 > 开发速度 > 工程美观。

## 当前基线

- Web v0.1 已形成可运行的本地优先学习闭环。
- 英语词汇已从 24 个样本词进入真实考研词频词库升级线。
- 文学内容仍以小样为主，**当前暂停扩充**。
- 自动云同步尚未接入。

## 当前唯一 P0：把英语做到长期可用

英语专项详细方案见 [`english/PLAN.md`](english/PLAN.md)。

### E0. 验收英语词汇 v1

先把现有 PR #3 变成可信基线。

完成标准：
- `npm test` 通过。
- `npm run build` 通过。
- 首次联网能加载完整考研词库目录。
- 缓存后二次打开可继续使用。
- 断网时有缓存继续用、无缓存明确降级且不丢学习状态。
- 旧 v0.1 未完成词组、收藏与复习记录仍可继续。
- Android 真机至少检查一次输入法、长列表、发音、滚动和短视口。

### E1. 词库可靠性与学习分层

目标：词库不再只是“远程能拉下来”，而是稳定、可复现、可分阶段学习。

完成标准：
- 固定一个已审核的 NETEMVocabulary 数据版本，不静默跟随上游变化。
- 词库数据与应用代码分离并保留来源/许可说明。
- 首次使用不依赖第三方 CDN 才能获得正式词库；远程源只用于显式更新或恢复。
- 至少提供三层学习范围：核心高频、2444 高频、完整 5530。
- 已学、到期、错词、收藏、已掌握在切换层级后仍保持稳定 ID 和记录。
- 词表默认不一次渲染全部 5530 行；搜索、筛选和长列表性能在手机可接受。

### E2. 智能学习闭环

目标：打开英语页后不用自己决定“今天背什么”。

默认队列按以下优先级生成：

1. 到期复习
2. 最近答错/拼错且需要强化的词
3. 未完成 session
4. 当日新词额度

保留三种核心训练：
- 跟打：看词完整输入，拼错后整词重输，避免错误肌肉记忆。
- 默写：看中文/释义回忆英文。
- 听写：听发音输入英文。

完成标准：
- 默认“智能模式”可以直接开始，不要求每次手动配置。
- 新词额度可调，但默认值适合日常碎片学习。
- 错词自动进入强化队列。
- 首次答错记录不会被后续订正覆盖。
- 完成本轮后可一键重练错词/遗忘词。
- 跟打不错误污染 FSRS；主动回忆结果才用于长期复习调度。

### E3. 单词信息质量

目标：背的不只是拼写，还能正确理解和辨析。

优先补充：
- 音标。
- 英/美发音选择；无法提供真实音频时保留浏览器 TTS 降级。
- 词性和核心中文义。
- 常见变形/异形词。
- 高频义优先，避免一屏塞满低频释义。

可考虑用明确许可的数据源补充基础词典字段；任何新数据进入仓库或运行链路前先记录来源与许可。

完成标准：
- 高频学习词不再普遍缺音标/词性。
- 释义顺序适合考研阅读，而不是机械展示所有字典义项。
- 点击词条能快速查看，不把训练主界面做成词典页面。

### E4. 错词、收藏、已掌握与统计

参考成熟产品，但只保留真正有学习价值的反馈。

完成标准：
- 错词本自动形成，可直接开始专项训练。
- 收藏可单独训练。
- 已掌握可恢复，不永久删除记录。
- 显示轻量统计：今日新学、今日复习、首次正确率、拼写错误数、当前到期量。
- 跟打可显示速度/正确率，但不做排行榜、积分商城或重度游戏化。
- 统计不增加额外打卡操作。

### E5. 语境训练

在孤立词汇训练稳定后再做，不提前拖慢主闭环。

方向：
- 高频难词配短语/搭配。
- 重点词可进入句子挖空输入，借鉴 Clozemaster 的“在语境中主动回忆”。
- 优先使用许可清晰或自行编写并人工核验的例句；不要批量抓付费词典、课程或版权不清的句子。

完成标准：
- 语境模式是可选强化，不取代快速背词。
- 每个句子训练仍然要求主动输入，而不是只做选择题。
- 例句来源/性质可追溯。

### E6. 英语真机体验与日常使用收口

完成标准：
- Android 连续训练至少一完整组无输入法遮挡/焦点异常。
- 桌面主要流程可以基本不碰鼠标。
- 手机主要流程可以单手完成。
- 发音失败有明确降级。
- 刷新、关闭、重开都能恢复未完成组。
- 真实使用一段时间后，只修高频卡点，不再继续堆模式。

## P1：英语完成后接单人薄云同步

在英语模块真正每天可用后，再做电脑 ↔ 手机连续学习；同步首先服务英语记录，不等文学内容完成。

原则：
- 本机永远先保存。
- 只同步学习状态，不建立复杂账号体系。
- 继续使用稳定事件 ID 和当前 schema，除非有明确迁移方案。
- 冲突处理优先“合并不丢数据”，失败必须明确提示。
- 先验证一个人的两台设备，不做多人协作。

完成标准：
- 电脑 → 手机与手机 → 电脑都能续学英语未完成组和复习状态。
- 断网学习后恢复联网可安全合并。
- 重复同步不制造重复记录。
- 手动导入/导出仍保留作为兜底。

## P2：文学与真题恢复开发

**当前暂停，不与英语并行扩张。**

英语和同步稳定以后，再恢复：
- 2023—2026 真题关联。
- 现当代文学 P0 主专题。
- 作品证据。
- 名词解释 / 简答 / 比较 / 论述派生练习。
- 文学“今日任务”真实驱动。

到那时仍遵守：有来源、稳定 ID、先答后看、不机械迁移旧 1101 条。

## 成熟产品中明确借鉴什么

### Qwerty Learner
- 输入与背词绑定。
- 拼错后整词重新输入，避免错误肌肉记忆。
- 音标、发音、默写。
- 速度与正确率作为轻量反馈。

### TypeWords
- 跟打 / 听写 / 自测 / 默写多模式，但默认流程要简单。
- 智能模式与自由模式分开。
- 错词本、收藏、已掌握。
- 例句、短语、词根等作为详情增强，不挤占训练主屏。

### Clozemaster
- 高频优先。
- 在句子中做主动回忆，而不是永久停留在孤立词表。
- 语境训练后置，作为已学单词的强化层。

### FSRS / Anki 经验
- 继续使用现有 `ts-fsrs`，不自己发明记忆算法。
- 忘记就按真正的失败记录，不用“会一点”伪装成成功。
- 保持评分含义稳定；未来如开放 retention 设置也保持简单，不暴露算法参数墙。

## 暂时不做

英语稳定前不做：
- 扩文学知识库。
- 整理新的文学真题页面。
- 重做文学 UI。
- 商业化、多用户、班级、教师后台。
- React / Vue 重构。
- 独立 Node 业务后端。
- 微服务、ORM、复杂权限系统。
- CRDT、实时协作、通用知识图谱基础设施。
- 为了“完整”一次性迁移全部旧知识点。
- 英语排行榜、积分商城、社交 PK 等与个人考研价值低的功能。

## 每次迭代的 Definition of Done

一项功能只有同时满足以下条件才算完成：

1. 用户能实际使用，而不只是代码存在。
2. 不破坏已有学习记录；若数据格式变化，有明确迁移或兼容方案。
3. 该跑的测试和构建已跑，并记录实际结果。
4. 页面功能至少做一次真实浏览器检查；涉及手机特性时不能用缩窄桌面窗口冒充真机。
5. 内容有来源，第三方资产有许可证记录。
6. `docs/开发进度.md` 已更新到真实远端状态。
7. PR 保持边界清楚，不把无关重构顺手混进去。
