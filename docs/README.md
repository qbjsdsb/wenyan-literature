# Wenyan 文档导航

这里是仓库文档入口。目标不是把文档做复杂，而是让任何后续 AI / 开发者在几分钟内知道：**现在做到哪、什么不能乱改、下一步做什么、改完怎么验收。**

## 先读这 6 个文件

1. [`../README.md`](../README.md) — 产品是什么、怎么运行、当前能力。
2. [`../AGENTS.md`](../AGENTS.md) — 后续开发必须遵守的原则与边界。
3. [`开发进度.md`](开发进度.md) — **当前状态唯一事实源（SSOT）**，每次阶段性工作结束必须更新。
4. [`ROADMAP.md`](ROADMAP.md) — 当前 English-first 总路线和后续阶段。
5. [`english/PLAN.md`](english/PLAN.md) — **当前最重要专项文档**，英语模块具体怎么做。
6. [`ARCHITECTURE.md`](ARCHITECTURE.md) — 当前代码、内容、学习状态和兼容边界。

## 文档分类

### 状态与验收

- [`开发进度.md`](开发进度.md)：当前分支、PR、已完成、未验证、下一动作。
- [`web-v0.1-validation.md`](web-v0.1-validation.md)：Web v0.1 已完成的真实浏览器验收与明确边界。
- [`../evidence/`](../evidence/)：与验收记录对应的截图证据。

### 当前专项：英语

- [`english/PLAN.md`](english/PLAN.md)：英语 E0–E6 推进路线、参考产品结论、词库策略、智能队列、错词/统计/语境/同步边界。

当前规则：**英语先做到长期可用，文学内容和真题扩充暂缓。**

### 产品与设计

- [`design/selected-reference.png`](design/selected-reference.png)：当前选定视觉方向，默认继续沿用。
- [`design/v0.1-qa.md`](design/v0.1-qa.md)：v0.1 视觉与功能 QA 摘要。

### 内容研究

- [`南师大现当代文学考研-二轮调研报告.md`](南师大现当代文学考研-二轮调研报告.md)：早期考研调研资料。它是研究输入，不等于当前产品事实源，也不应直接整段进入学习内容。

文学研究材料继续保留，但 English-first 阶段不主动扩充文学产品内容。

### 第三方与许可证

- [`third-party/`](third-party/)：字体、图标、FSRS、英语词库等第三方许可与来源说明。

## 文档维护规则

- **只允许一个“当前状态”文件**：`docs/开发进度.md`。不要再创建 `进度2.md`、`最新进度.md`、`交接-final.md` 之类平行文件。
- 总优先级写在 `ROADMAP.md`；具体英语产品决定写在 `english/PLAN.md`，不要把二者复制成两份不同版本。
- 验收记录写“实际做过什么”，不要把计划写成已经完成。
- 调研报告可以保留历史判断，但当前事实以官方来源和最新核验为准。
- 设计参考只保留真正会继续沿用的基准；不要堆大量未采用截图。
- 第三方代码、数据、字体、图标一旦进入项目，要在 `third-party/` 留下来源和许可说明。
- PR 是变更历史；文档只维护“现在是什么”和“接下来做什么”，避免重复写长流水账。

## 接手顺序

后续任何 AI / Work 接管当前阶段时：

`README → AGENTS → docs/开发进度 → ROADMAP → english/PLAN → 实际英语代码/PR`。

如果文档与远端实际文件或 PR 状态冲突，**以实际远端状态为准，并立即修正 `docs/开发进度.md`**。
